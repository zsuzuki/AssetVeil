# AssetVeil

[日本語 README](README_jp.md)

AssetVeil is a C++17 library and development CLI for encrypting and packing game
assets, then decrypting selected assets directly into memory at runtime.

Version 0.2 / format v2 uses libsodium's
[XChaCha20-Poly1305](https://doc.libsodium.org/secret-key_cryptography/aead/chacha20-poly1305/xchacha20-poly1305_construction).
It replaces the v1 transformation that allowed whole-file recovery from eight
known plaintext bytes, and removes deterministic nonce reuse. It is not DRM or
a guarantee of compliance with any asset license.

## Features

- File encryption and directory packing
- Fresh random 24-byte nonce for every encryption
- Authentication of file headers, pack paths/sizes/nonces, and asset payloads
- No plaintext returned on an authentication failure or wrong key
- Manifest loaded once; each runtime read seeks only to the selected asset
- No compression; file overhead is 60 bytes, pack overhead is 64 bytes plus
  60 bytes and the path length for each entry
- Existing file APIs and `Key` / `KeyGen` helpers retained

## Build

Requires libsodium >= 1.0.12 (`brew install libsodium` on macOS). CMake discovers
it through pkg-config or `CMAKE_PREFIX_PATH`.

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
```

For runtime-only builds:

```sh
cmake -S . -B build/runtime -G Ninja \
  -DASSETVEIL_BUILD_CLI=OFF -DASSETVEIL_BUILD_TESTS=OFF
cmake --build build/runtime
```

CLI and tests also default to off when included with `add_subdirectory`.
Link the game with `target_link_libraries(game PRIVATE assetveil)`. If using
shared libsodium, ship that library too. When linking static libsodium on
Windows, set `-DASSETVEIL_SODIUM_STATIC=ON`.

## CLI and keys

Use a high-entropy application secret generated separately for each game.
String keys must be non-empty and are mapped to 32 bytes with domain-separated
BLAKE2b. This fast mapping does not harden short, human-chosen passwords.

Generate a private 32-byte random value encoded as hex, without a trailing newline:

```sh
mkdir -p private
umask 077
openssl rand -hex 32 | tr -d '\n' > private/game.key

assetveil encode input.png input.png.av --key-file private/game.key
assetveil decode input.png.av restored.png --key-file private/game.key

assetveil pack assets game_assets.avp --key-file private/game.key
assetveil list game_assets.avp --key-file private/game.key
assetveil unpack game_assets.avp restored_assets --key-file private/game.key
```

Key files are consumed byte-for-byte, including newlines. Supply those same
bytes to the runtime API. `--key <key>` remains supported, but prefer
`--key-file` to keep secrets out of shell history and process arguments.
Listing requires the correct key to authenticate the manifest.

Write packs outside the input directory. Input symlinks are rejected.
Extraction rejects symlinks at the output root and within it. Use a dedicated
extraction directory that other processes cannot concurrently modify.

## C++ API

```cpp
#include <assetveil/assetveil.hpp>
#include "private/game_asset_key.hpp" // Generated by the private build pipeline

// game_asset_key may be a std::string, assetveil::Key or KeyGen.
auto decoded = assetveil::read_encoded_file("texture.png.av", game_asset_key);
if (!decoded.ok()) {
    // Handle the error; do not fall back to shipping/loading a plain asset.
    return;
}
const auto& bytes = decoded.data(); // Pass memory to the image/model loader

assetveil::PackReader pack("game_assets.avp", game_asset_key);
if (!pack.ok()) {
    return;
}
auto model = pack.read("models/player.glb");
if (model.ok()) {
    const auto& model_bytes = model.data();
}
```

For byte buffers, let the library generate the nonce:

```cpp
auto encrypted = assetveil::encrypt_bytes(input_bytes, application_secret);
if (encrypted.ok()) {
    auto decrypted = assetveil::decrypt_bytes(encrypted.data(), application_secret);
}
```

`PackReader` authenticates and caches metadata on construction, then
authenticates each payload on `read()`. `ok()` does not pre-verify every asset.
Construct a new reader after replacing a pack.

## Key obfuscation helper

```cpp
// Public example only; generate production keys from private build settings.
constexpr auto key = assetveil::KeyGen("example-only-do-not-use-in-production");
auto decoded = assetveil::read_encoded_file("texture.png.av", key);
```

`KeyGen` only obscures a literal's stored representation. It does not guarantee
that a compiler omits plaintext or that an attacker cannot recover the key.

## Migration from v1

- v1 files and packs are rejected. Re-encode/repack original assets and update
  the runtime library together.
- File APIs and `PackReader` keep their calling conventions. CLI `list` now
  requires a key.
- `obfuscate_bytes` / `deobfuscate_bytes` were removed. Use `encrypt_bytes` /
  `decrypt_bytes` and handle their `DataResult`. There is no caller-supplied
  64-bit nonce API.
- `PackEntry::checksum` remains for source compatibility but is always zero in
  v2. Authentication tags replace plaintext checksums.

See the [format and verification record](docs/security-review-2026-10-06.md).

## Shipping a game

Keep original licensed assets, key files, private configuration and generated
key headers out of public repositories and distributable bundles. Use
in-memory decoding in production; exclude the development CLI and plaintext
extraction/debug export paths. Encryption cannot prevent binary analysis or
runtime memory extraction when the game must possess the key. Check individual
asset licenses separately.
